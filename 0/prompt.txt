## 5. E7 round-circularity guard — concrete check

A label span is "seeded, not verified" when it is **byte-identical to what `_ensure_round_events_seeded` wrote and has never been touched since**. Concretely, given a `fight_events` row with `source='label'`, `kind='round'` for the reference fight, cross-reference it against the corresponding `rounds` row (same `fight_id`, `round_number = value`):

```
is_seeded_unverified =
    label_event.frame == round.start_frame
    AND label_event.end_frame == round.end_frame
```

That's the entire check available — `event_service._ensure_round_events_seeded` (`event_service.py:60-68`) copies `start_frame`/`end_frame` verbatim into `frame`/`end_frame` and never writes any other marker (no "edited" flag, no distinct `labeled_at` on the event row — `fight_events` has no per-row edited timestamp at all, only `created_at`, which doesn't change on a `PUT`). **This means exact-match-on-frame-bounds is the only honest signal available today**, and it has a known false-negative: a labeller who nudges a boundary by exactly 0 frames but genuinely reviewed it looks identical to never-touched. That's an acceptable false-negative for a first cut (errs toward *more* "unverified" labels, never fewer — matches honesty rule 2's bias). If ever it matters, `PUT /fights/{fight_id}/events/{event_id}` (`fights.py:218-223` → `event_service.update_event`, `event_service.py:97-121`) would need to start stamping something like `edited_at`, but that's a change to core labelling infra and explicitly out of scope for this Section-E-only plan — note it as a known limitation in the UI copy itself ("Seeded — not verified" rather than a false "verified").

Implementation: this check runs at **report-generation time in `ai/eval/score.py`/`report_io.py`**, not at display time — `RoundScore` (`score.py:135-157`) currently has no field for it. Add a per-matched-round `seeded: bool` (or a fight-level `rounds_seeded: dict[int, bool]`) computed by `score_rounds()`, which needs `labels` to know each round's seeded status. Since `FightLabels` (`schema.py`) has no notion of "seeded," the cleanest place to compute it is in `labels_db.build_labels()` (which already reads both `fight_events` and can join `rounds`) — stamp each `Round` label with whether it matched its seed, and thread that through into `RoundScore` in `score.py`. The frontend's `RoundsCheck.tsx` then reads `report.rounds.matched[i].seeded` and renders "Seeded — not verified" instead of the IoU % when true.
